SDN Worksheet Unit 2 Section 8
### Question

Scenario: A company is deploying an SDN solution and needs a controller that offers robust network virtualization capabilities, allowing for multiple isolated virtual networks on shared physical infrastructure.
Question: From the controllers mentioned (VMware NICIRA, OpenFlow-related, Plexxi, Cisco ONEPK), which would be the most relevant and why?

---

### Answer

**VMware Nicira** (specifically its Network Virtualization Platform, **NVP**, which evolved into **VMware NSX**) is the most relevant controller platform from the list for robust multi-tenant network virtualization.

* **Pioneer of Network Overlay Virtualization:**
* Nicira was explicitly built from the ground up to solve the problem of multi-tenant network virtualization in multi-hypervisor and multi-cloud data centers.
* It pioneered overlay network virtualization using encapsulation protocols (such as **VXLAN**, **NVGRE**, and **STT**), completely decoupling virtual tenant topologies (Layer 2 segments, virtual routers, and firewall policies) from the underlying physical IP fabric.


* **Complete Virtual Network Abstraction:**
* Through its software-based controller cluster and distributed virtual switches (like Open vSwitch on hypervisors), Nicira allows administrators to programmatically provision isolated, software-defined Layer 2 domains, distributed Layer 3 gateways, load balancers, and security groups on top of any standard shared physical infrastructure.
* Overlapping IP address spaces across distinct tenants are fully supported without requiring complex physical VLAN configurations or hardware reconfigurations.


* **Distributed Micro-Segmentation and Security:**
* In addition to basic segmentation, Nicira’s architecture embeds distributed firewalling and policy enforcement directly at the hypervisor virtual switch port level.
* This guarantees strict, granular isolation between tenant workloads even if they share the same physical server or subnet.


* **Why the Other Alternatives Are Less Suitable:**
* **OpenFlow-related (Generic):** While OpenFlow can be used as a southbound mechanism to implement virtual networks (e.g., via FlowVisor or OpenVirteX), standard OpenFlow controllers provide raw flow-table programming rather than an out-of-the-box, comprehensive overlay network virtualization platform.
* **Plexxi:** Focuses primarily on physical fabric orchestration, optical interconnects, and affinity-driven dynamic bandwidth steering rather than multi-tenant virtual overlay networks.
* **Cisco onePK:** Designed as a developer SDK for accessing proprietary features, routing engines, and ASICs on physical Cisco hardware (IOS, IOS-XE, IOS-XR), rather than functioning as a turnkey data-center network virtualization overlay platform.
